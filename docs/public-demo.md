# 公开工程说明

## 代码来源与边界

本公开实现根据原项目中的工程问题重新组织和编写，用通用规则与虚构标识演示计算逻辑。它没有复制客户规则库、业务枚举、实际门店、商品编号或供应商规划，也不能直接替代客户使用的 V2.2.4 程序。

```text
src/irestock_demo/
  domain.py       输入模型、校验、候选状态与决策证据
  rules.py        规则协议、注册表、分阶段执行
  allocation.py   补货分配、避款收敛、商品级守恒账本
  transfer.py     同品牌供需匹配、余量预算与调拨守恒
  storage.py      SQLite 原子持久化、输入指纹与审计索引
  exporter.py     JSON、CSV、Excel 输出与单元格安全
  web.py          本机 FastAPI 运行与历史结果接口
  cli.py          可复现的命令行入口
tests/            业务场景、随机不变量、事务与 API 测试
examples/         完全虚构的可运行样例
```

## 演示规则

| 阶段 | 规则 | 公开口径 |
| --- | --- | --- |
| 过滤 | G001 | 存在在单或在途时，停止新增计算 |
| 匹配 | G002 | `compatible=false` 的商品与门店组合阻断 |
| 数量 | Q001 | 月销量按覆盖天数折算，向上取整，并与有销/主推下限比较 |
| 分配 | A001 | 主推先分、有销保底，再按销量排序补齐，受仓库余量限制 |
| 冲突 | A002 | 指定互斥门店同一款式发生冲突，排除新增行并重新分配 |
| 调拨 | T001 | 同一 SKU、同一门店品牌之间，使用超出调出店目标的库存 |

这些是演示规则，不是客户最终业务口径。规则参数通过输入 JSON 的 `policy` 明确传入；合法的零值不会被默认值覆盖。

## 补货样例预期

执行 `examples/replenishment.json` 后：

- `SKU-RED` 仓库有 8 件，留 2 件，ALPHA 得 4 件，GAMMA 得 2 件。
- BETA 与 ALPHA 属于互斥组合。虽然 BETA 初次获得 `SKU-BLUE`，但两个 SKU 属于同一款式，因此 BETA 被排除。
- 释放出的 BLUE 数量重新分配给 GAMMA，最终 GAMMA 得 3 件；BLUE 仓库剩余账本为留货 2、分配 3、未使用 1。
- `SKU-TRANSIT` 命中 G001，`SKU-DISABLED` 命中 G002；这两行的目标和需求是 `null`，不是已计算的零。
- 分配经历两轮，审计中保留具体的冲突规则和被释放的数量。

## 调拨样例预期

执行 `examples/transfer.json` 后，DONOR 的目标库存是 2 件，9 件现货中有 7 件可调。MAIN 优先获得 4 件，SECOND 获得 3 件。OTHER 即使销量更高，也因门店品牌不同无法获得该供给。PENDING 因在途阻断，不进入新增需求计算。

移动后 DONOR 仍有 2 件；全部门店的 SKU-RED 库存总量仍是 9 件。

## 分配算法为什么会终止

每轮按照一致的排序键分配可用库存，然后按门店组合和款式检查冲突。新增冲突候选进入排除集合，下一轮重新分配全部可用量。

排除集合只增不减，每轮有冲突时至少排除一个候选，因此最多进行候选数加一轮计算。既有库存不会被计算过程删除；如果互斥双方已有库存，只阻断它们的新增分配。

该策略可能在复杂互斥图中留下未使用库存，因此它属于可解释的确定性贪心算法，而非全局最优求解器。

## 复杂度与审计设计

补货将候选按 SKU 分组排序，单轮分配约为 `O(N log N)`；冲突扫描还与互斥组合数、款式数有关。SKU 账本通过一次聚合构建，不重复全表求和。调拨按 `(sku, store_brand)` 索引供给池，避免对所有不相关门店逐一匹配；同一个供给池仍可能按目标需求重复排序。

规则决策包含 `rule_id`、阶段、原因和证据。商品级预留在同一 SKU 的各行保持一致，并注明 `reserve_scope=sku`。未执行数量计算的行保留空值；已经计算但没有缺口的行才用零值。

## 数据持久化与服务

每次 API 运行使用独立数据库连接。结果和规则证据在一个事务中保存，证据写入失败会回滚整个运行。输入 SHA-256 用于追溯该次请求内容，不作为自动去重或幂等机制。

服务默认只监听本机地址。公开案例没有登录、客户页面、用户权限和生产数据库迁移功能。演示输出生成在 `outputs/`，已被 `.gitignore` 排除。
